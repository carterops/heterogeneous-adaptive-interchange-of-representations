# Full-stack quality loop: isolated first pass

This is a post-v0.1.1 research note. It records a bounded method and observed failures, not a measured H-A-I-R quality advantage. The v0.1.1 authored evaluation cases and the public message wire format are unchanged.

## Hypothesis

A source-bound full-stack brief should help specialists preserve the user's task, product identity, data meaning, backend invariants, and interaction states. Design critique before implementation and independent backend and rendered reviews should catch consequential defects that software tests alone miss. A finding returns to the responsible specialist; the first result and failed evidence remain visible.

This would be weakened if the reviewed result still exposes unsupported values or writes, loses a permission boundary, fails on a source update, or makes the answer and next action harder to find.

## Frozen comparison and limits

The development case is a job P&L task with one complete dated synthetic job and one job with missing material coverage. The holdout is an isolated desktop attention-shutter task using a fake browser connection and mocked window capture. Tasks, source snapshots, fixtures, viewports, and a quality rubric were frozen before candidate repairs. The current condition is an existing product/runtime snapshot, **not a fresh paired model run under measured identical model settings**. First attempts and repair findings are retained in the private evaluation record.

| Observation | Current snapshot | Repaired isolated candidate |
| --- | --- | --- |
| Incomplete job daily margin | Numeric margin despite missing material coverage | Daily margin null; missing coverage and known zero are separate |
| Manual financial writes | Synthetic unauthenticated forecast/archive writes succeeded | Scoped security tests and a synthetic HTTP run reject unauthenticated, CSRF-invalid, and stale writes before mutation; authorized forecast/archive/restore complete |
| Desktop shutter with mocked capture/bridge | 1 of 9 bounded checks passed | First candidate 7 of 9; stale paused/private source tooltip found, repaired candidate 9 of 9 |
| Rendered job workflow | Mode hierarchy and mobile usability defects observed | Mode-specific decision regions built; first renders found contrast, disclosure, touch-target, focus, and status-copy defects; repaired 34-state build received a scoped independent visual pass |

The counts are reproducible synthetic checks, **not quality scores**. A synthetic source update changed the complete job's posted cost from $60 to $70 in the API and rendered daily view, recalculating margin to 68.18%; the incomplete job's daily margin remained null. A first write-probe script stopped after archive because it looked for the archived job in the active-only list. That failed probe is retained; a corrected all-jobs probe restored the synthetic job and passed stale forecast and archive/restore/ABA checks. The desktop candidate's real extension lifecycle, site-level grant revocation, real screen capture, and human use have not been tested.

An independent agent, blinded to the A/B condition labels and given only four static mobile screenshots, found the complete job's $160 actual profit on both screens. It judged the repaired screen easier for the incomplete job because that screen withheld margin and made the source-gap action explicit; the current screen displayed a 73.1% figure alongside a missing-material warning. This is a **blinded agent screenshot check**, not a human utility study or live workflow test.

## Runtime behavior under test

An isolated Astra candidate adds an opt-in full-stack quality brief carried through native H-A-I-R messages. It keeps the native specialist artifact distinct from each recipient rendering, records each recipient's acknowledgement, requires an independent design review before BUILDING, and requires independent backend and rendered-UI reviews before human-review eligibility. Runtime regressions found two state-machine bypasses in early candidates; both were repaired and the failed traces retained. Generic branch transition cannot claim human release authority. This mechanism is candidate code, not installed or promoted runtime behavior.

These product builds do not have prospective candidate-Astra handoff, acknowledgement, and pre-build design-review traces. The runtime mechanism passed isolated tests, but this run cannot attribute the product repairs to it. A new bounded iteration with actual specialist receipts is required before testing that causal claim.

The next hypothesis is narrower: prospectively enforced acknowledgements and pre-build critique may reduce source or permission mistakes and repair cycles under otherwise identical task, fixture, tool, and model settings. That comparison must save first attempts before repair; this record does not supply it.

No public H-A-I-R field was added: the observed loss was in runtime coordination and product implementation, not yet in the portable representation contract.

## What remains unmeasured

Blinded human answer-finding, comparable task time, preference, actual billed model/tool cost, and a paired current-versus-revised model run are **NOT_RUN** or **UNKNOWN**. A single isolated holdout cannot establish cross-project generalization. Architecture and compatibility decisions, external consumer checks, real permission-boundary checks, and human utility remain explicit gates; candidate tests and a scoped visual pass do not authorize release.
